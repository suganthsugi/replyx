# Contracts

Design-time API contracts for the feature. During implementation they are merged into the single
source of truth, `apps/api/openapi.yaml`, from which the web client is generated
(`scripts/generate-api-client.sh`).

| File | Covers |
|------|--------|
| [common.yaml](common.yaml) | Shared schemas, parameters and responses: error format, pagination, enums |
| [identity.yaml](identity.yaml) | `/auth`, `/me`, `/users`, `/invitations` (staff API) |
| [access.yaml](access.yaml) | `/roles`, `/permissions`, `/groups` |
| [tickets.yaml](tickets.yaml) | `/tickets`, `/tickets/{id}/messages`, `/views`, `/tags`, `/macros`, `/customers`, `/attachments`, `/search` |
| [operations.yaml](operations.yaml) | `/notifications`, `/dashboard`, `/audit-logs`, `/settings`, `/support-access`, `/sla-policies`, `/business-hours`, `/routing-rules`, `/automation-rules`, `/webhooks` |
| [customer.yaml](customer.yaml) | Customer API: `/customer/auth`, `/customer/conversation`, `/customer/messages`, `/customer/attachments` |
| [platform.yaml](platform.yaml) | Platform console API on the console host: `/platform/*` |
| [realtime-events.md](realtime-events.md) | Socket.IO connection, rooms, subscription rules, event envelope and payloads, catch-up |
| [webhook-events.md](webhook-events.md) | Outgoing webhook payloads and signature verification |

## Conventions (all APIs)

- **Base paths**: staff API `https://{tenant}.replyx.app/api/v1`, customer API
  `https://{tenant}.replyx.app/api/v1/customer`, platform API
  `https://console.replyx.app/api/v1/platform`. The tenant always comes from the host (research D2).
- **Auth**: session cookie (`rx_session`). State-changing requests must send `X-CSRF-Token`
  matching the `rx_csrf` cookie.
- **Schemas**: explicit request and response schemas only. Storage models are never exposed
  (constitution IX). Unknown request fields are rejected (`VALIDATION_FAILED`).
- **Errors**: always
  `{ "error": { "code": "TICKET_NOT_FOUND", "message": "Ticket not found", "details": [...] } }`.
  `details` is optional and only used for validation errors (`[{ "path": "title", "issue": "too_long" }]`).

  | HTTP | When | Example codes |
  |------|------|---------------|
  | 400 | Invalid input | `VALIDATION_FAILED` |
  | 401 | No or expired session | `UNAUTHENTICATED` |
  | 403 | Authenticated, resource visible, action not allowed | `PERMISSION_DENIED` |
  | 404 | Missing, **other tenant's**, or **not visible to you** | `*_NOT_FOUND` |
  | 409 | Conflict with current state | `TICKET_STATE_CONFLICT`, `ROLE_IN_USE`, `GROUP_HAS_TICKETS`, `ALREADY_TRIAGED` |
  | 413 / 415 | Attachment too large / type not allowed | `ATTACHMENT_TOO_LARGE`, `ATTACHMENT_TYPE_NOT_ALLOWED` |
  | 423 | Account locked | `ACCOUNT_LOCKED` |
  | 429 | Rate limited | `RATE_LIMITED` (with `Retry-After`) |
  | 503 | Tenant suspended | `TENANT_SUSPENDED` |

  **403 vs 404 rule**: if the caller cannot *see* the resource (other tenant, or a ticket outside
  their group access) the answer is 404, identical to a missing id (FR-003). 403 is only used when
  the caller can see the resource but lacks the action (e.g. view but not edit).
- **Pagination**: cursor-based. Query `?limit=50&cursor=...` (limit 1–100, default 25). Responses
  wrap lists as `{ "items": [...], "nextCursor": "..." | null }`.
- **Idempotency**: message sends carry `clientMessageId` (UUID generated by the client). Other
  creating POSTs accept an optional `Idempotency-Key` header (kept 24 h).
- **Concurrent edits**: ticket PATCH changes only the fields sent. Concurrent edits apply in
  commit order, so for the same field the later change wins, and both are recorded in history
  and pushed live to everyone viewing (spec Assumptions). Replies are never rejected or lost.
  Triage is the exception: the second triage of the same ticket gets `409 ALREADY_TRIAGED`
  (spec User Story 5, scenario 6).
- **operationId**: omitted in these design files. When an endpoint is merged into
  `apps/api/openapi.yaml` it gets a camelCase `operationId` (`listTickets`, `triageTicket`),
  because orval names the generated hooks after it.
- **Timestamps**: ISO 8601 UTC strings. **Ids**: UUID strings. Ticket numbers are integers and
  only appear in the staff API.
