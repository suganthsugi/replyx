## Rules

1. **Append in the same transaction as the state change.** `append` takes the `tx` from
   `withTenant`; never publish, emit to a socket, or enqueue a BullMQ job directly from a service
   (constitution IV, V).
   ```ts
   // target shape (tasks.md T034, research D7)
   await withTenant(ctx, async (tx) => {
     const msg = await this.messages.insert(tx, input);
     await this.outbox.append(tx, {
       type: 'message.created',
       actor: ctx.actor,
       payload: toStaffMessage(msg),
       customerPayload: msg.visibility === 'public' ? toConversationMessage(msg) : undefined,
       streams: msg.visibility === 'public'
         ? [`ticket:${msg.ticketId}`, `conversation:${msg.customerId}`]
         : [`ticket:${msg.ticketId}`],
     });
   });
   ```
   Wrong: `await tx.commit(); this.server.to(room).emit('message.created', msg)`
   Wrong: `await this.queues.notifications.add(...)` inside a service (consumers read events).

2. **Event ids are UUIDv7, generated by `append`.** Callers never pass `id` or `seq`; `seq` is
   assigned only by the relay.

3. **Type naming: `<resource>.<past_tense_verb>`**, lowercase snake_case, declared once in
   `event-types.ts` with its payload type. Existing names in the contracts: `ticket.created`,
   `ticket.updated`, `ticket.assigned`, `ticket.closed`, `ticket.state_changed`,
   `ticket.removed_from_view`, `ticket.reminder_reached`, `message.created`, `message.moved`,
   `message.read`, `notification.created`, `access.changed`, `access.revoked`,
   `session.revoked`, `tenant.suspended`. Customer types are `conversation.*`
   (`conversation.message`, `.delivery`, `.status`, `.resolved`). Reuse before inventing.
   Wrong: `TicketCreated`, `ticket-created`, `ticket.create`.

4. **Streams are tenant-less keys; rooms are `t:{tenantId}:` + key.** Keys:
   `user:{userId}`, `views:{userId}`, `ticket:{id}`, `tickets:group:{groupId|ungrouped}`,
   `conversation:{customerId}`. A group move lists both old and new `tickets:group:*` streams,
   and adds `ticket.removed_from_view` on the old group.
   Wrong: `streams: ['t:acme:ticket:1']` (tenant is added by the relay/gateway, never by callers).

5. **Customer streams get `customerPayload` only.** Any event with a `conversation:*` stream
   MUST set `customerPayload`, built by the messaging projector (`ConversationMessage`,
   `FriendlyStatus`, `ResolvedMarker` from `contracts/customer.yaml`). The projection never
   contains ticket id/number, state, group, owner, priority, SLA or internal notes (principle
   XI, research D9). Internal notes never get a `conversation:*` stream.
   Wrong: `customerPayload: { ...payload, ticketNumber }` / `customerPayload: payload`.

6. **Relay (worker only)** — leader via `pg_try_advisory_lock`; others idle. Wakes on
   `LISTEN outbox_new`, polls every 500 ms; reads `published_at IS NULL` in `id` order; assigns
   monotonically increasing `seq`; fans out to BullMQ (payload `{ tenantId, eventId }`) and the
   `@socket.io/redis-emitter`; sets `published_at`; prunes published rows > 7 days; exports
   `outbox_relay_lag_seconds`. The relay reads `outbox_events` across tenants with the
   `replyx_platform` pool (outbox is a global table, data-model.md).
   Wrong: running the relay in `main.api.ts`, or using a DB sequence for `seq` (commit-order gaps).

7. **Envelope** sent to clients (contract): `{ id, seq, stream, type, occurredAt, actor, data }`.
   Ephemeral signals (`typing`, `presence`, `viewing`, `availability.changed`) have no `id`/`seq`,
   live only in Redis with 30 s TTL (`presence.service.ts`) and are never written to the outbox
   or ticket history.

8. **Gateway** — Socket.IO path `/rt`, `@socket.io/redis-adapter`, namespaces `/` (staff) and
   `/customer`. Handshake authenticates `rx_session` against the host's tenant and audience,
   else `connect_error { code: 'UNAUTHENTICATED' }`. Staff auto-join `user` + `views` and
   `tickets:group:*` from effective access; customers auto-join their own `conversation` and
   cannot subscribe to anything else. Every `subscribe` goes through `PolicyService.can`; no
   view access → ack `{ ok: false, error: { code: 'NOT_FOUND' } }` (same as nonexistent).
   All client messages use acks `{ ok: true, ... }` / `{ ok: false, error: { code, message } }`.
   ```ts
   // target shape (contracts/realtime-events.md, T037)
   @SubscribeMessage('subscribe')
   async subscribe(socket: AuthedSocket, { stream }: { stream: string }) {
     const ticketId = parseTicketStream(stream);
     const d = await this.policy.can(socket.data.ctx, 'ticket.view', { ticketId });
     if (d !== 'allow') return { ok: false, error: { code: 'NOT_FOUND', message: 'Not found' } };
     await socket.join(`t:${socket.data.ctx.tenantId}:${stream}`);
     return { ok: true };
   }
   ```
   Wrong: joining a room from a client-supplied string without a policy check.
   Wrong: returning `FORBIDDEN` for another tenant's or an inaccessible ticket.

9. **`sync` catch-up** (`sync.handler.ts`): input `{ streams: [{ stream, afterSeq }] }`. Replay
   events with `seq > afterSeq` for streams the socket may see **now** (re-check access), in
   `seq` order, then ack `{ ok: true, upToSeq }`. Cursor older than retention (7 days) →
   `resync_required` for that stream; client refetches REST. Customer sockets replay
   `customer_payload` only.

10. **Disconnect and revocation.** On `session.revoked` disconnect with `{ code: 'SESSION_REVOKED' }`;
    on `tenant.suspended` with `{ code: 'TENANT_SUSPENDED' }`. On `access.changed`
    (`bumpAccessVersion(tx, tenantId, reason)` from `authorization/access-version.ts`, T032),
    recompute each connected staff user's rooms in that tenant, leave rooms no longer allowed,
    emit `access.changed { accessVersion }` and `access.revoked { ticketIds?, groupIds? }` to
    their `user` room within 2 s (FR-025, SC-011). Any role/group-access/user-role/user-status
    change MUST call `bumpAccessVersion` in its transaction.

11. **Consumers are idempotent.** Every BullMQ consumer extends `IdempotentHandler`
    (`jobs/idempotent-handler.ts`): skip if `(consumer, event_id)` exists in `processed_events`,
    run inside `withTenant` built from the job's `tenantId`, insert the `processed_events` row in
    that same transaction. 5 attempts, exponential backoff, then dead-letter queue.
    ```ts
    // target shape (research D12, T036)
    export class AuditConsumer extends IdempotentHandler<DomainEvent> {
      readonly consumer = 'audit';
      async handle(tx: Transaction, event: DomainEvent) { /* tenant-scoped work only */ }
    }
    ```
    Wrong: a consumer that inserts into `processed_events` in a separate transaction, or reads
    `tenantId` from `event.payload` instead of the job.

12. **Logs** carry `eventId`, `tenantId`, `jobId`; never log `payload`/`customerPayload`
    (message bodies, principle X).

## Tests that must exist (T049, D9)
- Event published only after commit; rollback publishes nothing.
- Gap-free `seq` in commit order under concurrent writers; single leader; re-publish not duplicated.
- `sync` replays missed events; `resync_required` past retention; revoked access excludes replay.
- Customer projection contract test: no internal fields; internal notes produce no customer event.
